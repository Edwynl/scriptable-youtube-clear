# Scriptable YouTube Clear

在 iPhone 的 [Scriptable](https://scriptable.app) 里打开 m.youtube.com，并注入一段脚本，让网页版 YouTube 更好用：

- 左侧悬浮面板：搜索 / 返回 / 首页
- 搜索弹窗：实时搜索建议 + 本地最近搜索记录
- 隐藏广告位，自动跳过或快进视频广告，广告后恢复原来的倍速和静音
- 锁屏 / 后台继续播放，锁屏界面和控制中心的媒体控制
- 被微信语音、来电等打断时让出声音，结束后自动继续
- 横屏 = 全屏（和 YouTube App 一样），全屏时最小化自动进入画中画
- 自动点掉“仍在观看？”弹窗
- 偏好 1080p 画质

测试机型：iPhone 14 Pro Max

## 安装

1. 在 Scriptable 里新建脚本，把 `YouTubeClear.js` 的全部内容粘贴进去。
2. 必须在 **App 内运行**：在快捷指令里添加 Scriptable 的 “Run Script” 动作，并打开 **Run In App / 在 App 中运行**，再把快捷指令添加到主屏幕。
   - 不要用普通的扩展模式运行，也不要用快捷指令的小窗 WebView，否则脚本会提示并退出。

## 画中画

iOS 只有在视频处于**原生全屏**时，切到后台才会自动进入画中画；竖屏内联播放时系统不会自动开（这是 WebKit 的限制，网页脚本无法绕过）。所以：

- **横屏**：脚本会可靠地保持全屏，直接最小化即可进入画中画
- **竖屏**：先点 YouTube 播放器的全屏按钮，或把手机转横屏，再最小化
- 需要打开 iPhone 的 **设置 → 通用 → 画中画 → 自动开启画中画**

在横屏时手动退出全屏，这个视频就保持内联（此时最小化不会有画中画）；转回竖屏再横屏，或换一个视频，会重新自动全屏。

没出现画中画时，回到 App 打开调试面板，看最小化那一刻的日志：
- `blur ignored (native player)`：最小化时在全屏里（正常）
- `bg visibilitychange (hidden) mode=…`：进入后台时的模式。`picture-in-picture` 表示画中画已开启；`inline` 表示最小化时不在全屏；`fullscreen` 表示在全屏但系统没有开画中画（检查上面的系统设置）

## 暂停是怎么判断的

脚本要同时做到两件事：**切后台时系统造成的暂停要自动恢复**（后台播放），**用户的暂停要尊重**。难点是 iOS 原生全屏、画中画、拔耳机、来电造成的暂停，网页都收不到触摸事件，看起来和“系统暂停”一样。规则如下：

| 暂停发生时 | 处理 |
|---|---|
| 刚有触摸 / 锁屏控制中心点了暂停 | 用户暂停 |
| 画中画里 | 用户暂停（画中画本来就是后台用的） |
| 原生全屏里，页面在前台 | 先当作用户暂停；1 秒内页面真的进入后台（锁屏）→ 撤销并恢复 |
| 内联播放，页面在前台 | 先当作暂停（拔耳机、来电）；1 秒内进入后台 → 撤销并恢复 |
| 页面已在后台 | 系统暂停 → 自动恢复 |
| YouTube 自己在后台调用 `pause()` | 拦截 |

“1 秒内进入后台就撤销”是为了处理一个时序问题：切后台时，系统的暂停有时比后台事件早到几十毫秒。

## 调试面板

在屏幕**左上角 1.6 秒内连点 4 下**打开，再点 4 下关闭。第一行：

| 字段 | 含义 |
|---|---|
| `mode` | 视频当前模式：`inline` 内联 / `fullscreen` 全屏 / `picture-in-picture` 画中画 |
| `pip` | 这个 WebView 是否支持画中画 |
| `hidden` | 页面是否真的在后台（绕过脚本自己的可见性伪装） |
| `bg` | 脚本是否认为已切到后台 |
| `userPaused` | 是否被记为用户暂停（不会自动恢复） |
| `inAd` | 是否正在播放广告 |
| `keepAlive` | 保活音频是否在运行 |
| `interrupted` | 是否正被别的 App 打断（微信语音、来电） |
| `audio` | AudioContext 状态，打断时为 `interrupted` |

## 版本记录

### v1.8.1：修复第二条微信语音被抢

第一条语音结束、视频恢复播放时，系统会唤醒后台页面并发出 `resume` / `focus` 事件。v1.8.0 把它当成“回到 App”：清空后台计时、结束打断状态，之后第二条语音开始时的暂停被当成“刚切后台”，立即恢复播放，把声音抢了回来。

- 页面仍在后台时收到的 `resume` / `focus` / `pageshow` 一律忽略
- “进入后台多久”改为在主循环里按页面真实可见性计算，不依赖事件
- 新增 2 个测试场景（连续两条语音，普通后台 / 画中画）：40/40 通过

### v1.8.0：微信语音、来电时让出声音

后台播放时听微信语音会被打断：iOS 暂停视频把声音交给微信，旧版却把它当成“切后台造成的暂停”立刻恢复，保活音频也每 1.5 秒抢一次音频会话。

- 进入后台 1.5 秒后才出现的暂停，视为被别的 App 打断（微信语音、来电、Siri、闹钟），不再恢复播放
- 监听 AudioContext 的 `interrupted` 状态：打断期间保活音频不再抢音频会话
- 打断结束（`interrupted` 解除）或回到 App 时自动继续播放；打断前本来就暂停的不会继续
- 前台来电：通话中暂停，挂断后继续（v1.6.0 起前台系统暂停会一直停着）
- 后台拔耳机没有打断信号，保持暂停，不会外放
- 调试面板新增 `interrupted` 和 `audio`
- 新增 6 个测试场景：38/38 通过（v1.7.1 33/38）

### v1.7.1：修复画中画出现约 1 秒就消失

画中画开始、页面还没进入后台的那一小段时间里，v1.7.0 有三处和 v1.4.0 不同：

- YouTube 自己调用 `pause()` 被当成前台暂停放行（v1.4.0 会拦截）
- 画中画里出现的暂停一律当成用户点的，不再恢复；但“全屏 → 画中画”切换时系统可能暂停一下
- 网页 JS 可以把视频拉出画中画（两个版本都没拦）

**修复**
- 原生全屏 / 画中画里，网页 JS 发起的 `pause()` 一律拦截（用户在这两种模式下点的暂停来自系统控件，不经过网页 JS）
- 进入画中画后 2 秒内出现的暂停当作切换过程造成的，自动恢复；“全屏里暂停，1 秒内变成画中画”也撤销暂停
- 画中画中，没有用户操作时，网页 JS 调用 `webkitSetPresentationMode` / `webkitEnterFullscreen` / `webkitExitFullscreen` / `exitPictureInPicture` 想离开画中画，一律拦截
- 上滑回主屏幕（blur）和离开画中画后 2 秒内，不自动全屏，避免在过渡期插手
- 日志记录播放模式变化时是在播放还是暂停
- 新增 6 个测试场景：32/32 通过（v1.7.0 27/32）

### v1.7.0：修复最小化后没有画中画

v1.4.0 横屏时每 300ms 强制全屏，所以最小化时总在全屏里，能自动画中画。v1.5.0 把它改成“只在转横屏那一下尝试一次”，以下情况就进不了全屏，也就没有画中画：

- 转横屏时视频还没加载好（只试一次，不再重试）
- 先横屏、再打开视频（没有“转屏”这个动作）
- 直播（时长是无限大，被 v1.6.0 从 Codex 版采用的时长检查排除）
- 进过一次画中画后：v1.6.0 从 Codex 版采用的“全屏中”标记可能不会被清掉，之后不再自动全屏

**修复**
- 横屏 = 全屏：在主循环里持续检查，视频没加载好会重试（每个视频最多 3 次），先横屏再开视频也会全屏，直播也算，从画中画回到页面后自动回到全屏
- 保留 v1.5.0 的改进：在横屏时手动退出全屏，这个视频不再被拉回（进入画中画、切后台、转回竖屏都不算手动退出）
- 判断全屏 / 画中画只看视频元素的实时属性，删掉容易过期的标记
- 如果 YouTube 给视频加了 `disablepictureinpicture`，自动去掉
- 调试面板新增 `mode` 和 `pip`；切后台时的日志记下当时的播放模式，方便排查
- 播放页也包括 `/live/` 直播链接

### v1.6.0：合并 Claude v1.5.0 与 Codex v1.5.0

以 Claude 版为基础，吸收 Codex 版的优点，并修复两个版本都有的问题。

**两个版本都有的问题（本版新修）**
- 前台被系统暂停（拔耳机、来电）后，之后一锁屏视频就自己开始播放（外放）
- 监听 `window` 的 blur 用了捕获模式，会收到输入框等元素的失焦，被误判为切后台；还会拦截页面上所有元素的 blur 事件
- `visibilitychange` 在回到前台时也会触发，旧版把它也当成了切后台

**来自 Codex 版**
- 只在真正处于后台时拦截 `pause()`；前台的暂停一律尊重（旧版前台也会拦截）
- 进入全屏时的 blur 不算切后台，全屏开始时重置后台状态
- 锁屏“下一个”只点击一次（旧版会点两次，可能连跳两个视频）
- 每个锁屏动作单独注册，某个动作不被支持时不影响其他动作
- 锁屏进度条随每次循环更新
- 用户暂停后停止保活音频省电（本版改为暂停超过 10 分钟才停，短暂停仍能从锁屏直接继续）
- 广告和 UI 修复合并进一个主循环，去掉单独的 300ms 定时器
- 广告期间不设置画质
- 搜索框：关闭自动大写和拼写检查，外接键盘 Esc 关闭
- 侧边按钮加 `role` 和 `aria-label`，旁白可读
- `'use strict'`、搜索建议空值保护、返回首页的兜底跳转

**保留 Claude 版的做法（Codex 版这几处有问题）**
- 画中画里的暂停当作用户暂停（Codex 版会自动恢复）
- 全屏时锁屏仍然后台续播（Codex 版会停住）
- 横屏自动全屏只在转为横屏时触发一次，只在播放页（Codex 版退出全屏后会被拉回，首页预览视频也会全屏）
- 广告中途切换视频时不重置广告状态（Codex 版会让下个视频停在 16 倍速静音）
- 广告结束只撤销我们设置的 16 倍速，恢复的是正片时的倍速和静音
- “仍在观看？”弹窗按弹窗文字匹配，2 秒检查一次，用 `textContent`
- 原生方法只保存一次、监听器统一登记，`destroy()` 完整还原
- 整页刷新后自动重新注入

**未采用**
- Codex 版开启了锁屏 ±10 秒快退快进：iOS 会因此把锁屏的“上一个 / 下一个”换成 ±10 秒按钮，所以保持关闭
- Codex 版拖动锁屏进度条会同时开始播放：本版暂停中拖动保持暂停

### v1.5.0

修复全屏时无法暂停；横屏全屏只触发一次；强制 HD 不再轮询；广告后恢复静音和倍速；弹窗检测降频；搜索建议丢弃过期结果；`destroy()` 完整还原；整页刷新后自动重新注入。

### v1.4.0
